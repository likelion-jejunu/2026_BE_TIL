### 2. 핵심 정리 (내 언어로)
- 상속: 기존에 있던 클래스를 재사용해서 새로운 클래스를 만드는 것으로, 더 상위 개념의 클래스의 내용을 가져온다. extends를 사용하여 상속받는다. is-a 관계여야 사용됨.
- 오버라이딩: 부모 클래스의 매서드를 자식 클래스에서 다르게 동작하도록 재정의할 때, 사용되는 것. 가독성과 실수를 방지하기 위해 @override이라고 적어둠.
- 오버라이딩 vs 오버로딩: 오버라이딩은 부모메서드를 자식이 재정의하는 것이지만, 오버로딩은 이름이 같고 매개변수가 다른 것임.(오버라이딩은 덮어쓰는 것, 오버로딩은 같은 이름에 여러 버전의 짐을 싣는 것)
- 다형성: 같은 메서드 호출이지만 객체에 따라 다른 실행 결과가 나타나는 것. 다형성이 성립하려면 상속과 오버라이딩이 되어야 함. 상속을 통해 Animal을 extends하고 오버라이딩을 통해 각각 재정의하는 것.
- 추상화: 부모 역할은 제공하지만, 직접 만들어서 사용하는 것은 abstarct를 사용해서 막고싶은 것이다. 이 메서드를 상속받은 자식 클래스가 반드시 오버라이딩을 해서 구현해야 한다. 안하면 컴파일 오류 발생함.
- 인터페이스: 추상 메서드만 모아놓은 것. public abstract 생략 가능함. 다중 구현(다중 상속)을 지원한다. 인터페이스를 구현하기 위해 implements를 사용.
- 디폴트 메서드: 인터페이스에 새 메서드를 추가하면 기존 클래스에서 컴파일 에러가 나기에 이를 해결하기 위해 default를 사용.

### 3. 실습 / 과제 / 결과물
- 실습2 STEP3에서 코드 에러가 발생하는 이유
  : feed(), clean()은 부모인 Animal 추상 클래스 안에서 선언되어 있어서 호출이 가능하지만,
  play()는 Animal이 아닌 Playable에 정의되어 있어 Animal 안에 play()를 찾지 못해서 에러가 난 것이다.
  -> 이를 해결하기 위해, Animal이 Playable을 함께 extends/implements하도록 구조를 수정하거나 배열 타입을바꾸면 해결이 가능하다.

- 자바 컬렉션 프레임워크 (List, Map) 정리
1) List
   : 순서가 있고, 데이터의 중복 저장을 허용하는 자료구조. 대표적으로 ArrayList를 사용.
   내부적으로 배열을 이용하기 때문에 데이터 조회 속도가 빠르다. 그래서 순차적으로 데이터를 추가하거나 전체 데이터를 순회하며 꺼낼 때 사용하면 좋다.

2) Map
   : 순서가 유지되지 않고, 키(Key)와 값(Value)을 쌍으로 저장하는 자료구조. 대표적으로 HashMap을 사용.
   데이터를 찾을 때 전부를 다 뒤지는 것이 아닌, 고유 Key 값을 쳐서 Value를 찾아내서 검색 속도가 매우 빠르다. 그래서 특정 대상을 고유 키로 바로 매핑할 때, 유용함.
